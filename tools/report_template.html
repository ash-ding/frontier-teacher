Which problems teach?

Nine GRPO runs — three models, each trained on three bands of its own measured problem difficulty — plus matched controls, all evaluated on the same three benchmarks at a shared budget of 10,240 student rollouts. Plain GRPO, no teacher: the control that a teacher-side method has to beat.

1 · Fixed difficulty bands

Each curriculum is a slice of the 11,996-problem MATH pool held fixed for the whole run, cut by the student's own measured pass@1. This is the control the teacher has to beat.

x-axis: student rollouts, 0 to 10,240. Each panel scales to its own data — the three models sit at very different absolute levels, and a shared axis would flatten every curve into a line. Compare within a panel; read across panels using the labelled change from baseline.

2 · The same panels, with a teacher-written curriculum

Claude Opus 4.8 chose 16 problems per step, after evaluating the current checkpoint on problems it wrote itself. It was given no reference data and never saw these curves. Everything else — student, group size, batch size, sampling, GPU count — is identical to the bands above, so the problems are the only thing that differs.

Every curve here is scored on the four fifths of each benchmark the teacher could not see. The per-step reference tests are the other fifth, and their problems and the student's full generations on them land in the run directory the teacher reads — it did read them. The bands never had that channel, so scoring the whole benchmark would compare them on unequal terms. Section 3 measures whether the leak was used.

3 · Did the teacher use what it could see?

Two lines per panel, from the same four evaluations of the same checkpoints, split only by which problems they are computed over: the fifth the teacher could read in the run directory, and the four fifths it could not. Same sample counts, same grader. A curriculum drawn from what it saw would push the seen line above the held-out one and keep it there.

Method

  • Training. GRPO in verl 0.9.0, vLLM rollouts, reward from the same grading.py the evaluation uses, so a gain cannot come from the grader. Every run starts from the released weights.
  • Group size follows the band. A GRPO group whose rollouts are all wrong contributes no gradient — 48.2% of groups at pass@1 8.7% with G=8, so the extreme bands use G=32 and the middle band G=8. Batch sizes are set against G to hold 512 rollouts per step, which is what puts the curves on one axis.
  • Evaluation. MATH-500 at 4 samples, AIME 2020–2024 (150 problems) at 8, HMMT Feb 2025 / Nov 2025 / Feb 2026 (93 problems) at 16. pass@k uses the unbiased estimator. AIME and HMMT never appear in training — they are pure transfer.
  • Significance quoted in the text is a two-level bootstrap over both problems and generations. Re-running one identical evaluation of one identical model returned AIME pass@4 15.3% and 12.0%, so resampling problems alone understates the interval by about a third.

What this is not

Frontier Teacher — testing whether frontier models can serve as teachers to better train smaller models on mathematics. This page is the no-teacher control: plain GRPO, which any teacher-side method has to beat.
